# CLAUDE.md: Neokeys

NeoKeys: the fleet's keyboard-shortcut registry, and its own reference implementation. Shortcuts are declared as data, so the `?` sheet is generated (never hand-maintained), reserved keys are refused out loud, and single-key bindings meet WCAG 2.1.4 via a remap/disable panel. Ships `H` chrome toggle (opt-in `neo-chrome-toggle`, ~105px back) and `G` fleet switcher over the registry. **`js/neokeys/` imports nothing from the site**. That constraint is what lets it become a kit under packages/neorgon-ui/ by copying one directory (neokeys.neorgon.com)

**Live:** neokeys.neorgon.com · **Port:** 8865

## Run

```bash
make serve
```

Then open http://localhost:8865. It must be served over HTTP. The app is ES modules, and `file://` blocks them.

## Data

- `localStorage['neokeys-prefs']`
- `data/`: 1 file(s)

## Conventions

- Zero build step. Plain ES modules loaded by `js/app.js`.
- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- No single JS file over ~500 lines. It currently holds.

## Gotchas

- **Shortcuts are declared as data.** The `?` sheet is generated from that
  declaration and must never be hand-maintained. A hand-edited sheet goes stale
  the first time a binding changes.
- Reserved keys are refused out loud rather than silently ignored, and single-key
  bindings meet WCAG 2.1.4 through the remap/disable panel. Removing that panel
  makes the single-key bindings an accessibility failure.
- **`js/neokeys/` imports nothing from the site.** That constraint is the whole
  point: it is what lets the directory become a kit under `packages/neorgon-ui/`
  by copying one directory. A single import from `../state.js` destroys that.

## Do not touch

- `js/neorgon-*.js` and `css/neorgon-*.css`: vendored kits, regenerated by `packages/neorgon-ui/sync-*.sh`.
